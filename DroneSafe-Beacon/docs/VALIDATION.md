# 검증 이력과 남은 작업

기준일: 2026-10-11 (Asia/Seoul). 기존 NU54 실험 장치의 관찰과 새 소스 패키지의 빌드 검증을 구분합니다. 원시 로그에는 장치 식별 정보가 있어 GitHub에 포함하지 않고 요약만 옮겼습니다. 재현되지 않은 결과를 새 시험 성공으로 계산하지 않습니다.

## 펌웨어 기준

드론은 `reliability2`, 탐색기는 그 위에 보행 필터를 추가한 `walkfilter1` 소스입니다. GitHub 정리 작업은 펌웨어 C/H와 보드 설정을 바꾸지 않고, 문서 및 PC별 경로·USB 인자를 정리한 작업입니다. 이 작업 중 실제 보드를 다시 업로드하거나 새 소유자를 등록하지 않습니다.

## 새 소스 패키지 clean build

2026-10-11에 새 DroneSafe 프로젝트 경로에서 `Build-NU54Secure.ps1`로 두 역할을 각각 빌드했습니다. 사전에 존재하지 않던 별도 빌드 루트를 사용했으며, SDK는 NCS v3.4.1, 보드 타깃은 `nrf54l15dk/nrf54l15/cpuapp/nu54dk`입니다. 두 프로세스 모두 종료 코드 0과 `BUILD_COMPLETE ... upload_performed=0`을 확인했습니다.

| 역할 | 결과 | FLASH 사용 | RAM 사용 | 앱 HEX (빌드 루트 기준) |
| --- | --- | --- | --- | --- |
| 비콘 `drone` | 성공 | 297,320 B | 78,162 B | `drone/drone/zephyr/zephyr.hex` |
| 탐색기 `searcher` | 성공 | 352,528 B | 87,828 B | `searcher/searcher/zephyr/zephyr.hex` |

실행 형식은 `./Build-NU54Secure.ps1 -Role <drone 또는 searcher> -SdkInstallRoot <SDK 설치 루트> -SdkManager <SDK 관리자 경로> -BuildRoot <별도 빌드 루트>`입니다. 개별 경로는 사용하는 PC에 맞춰 지정합니다. 기존 SDK의 deprecated `NRF_PLATFORM_LUMOS` 및 experimental `BT_CHANNEL_SOUNDING`/`BT_CS_DE` 경고는 남아 있습니다.

이는 정리된 소스와 상대 경로 구성이 컴파일·링크되어 HEX로 생성됨을 검증한 결과입니다. **이번 작업에서 USB 연결 열기, 보드 리셋, 펌웨어 업로드, 새 소유자 등록 또는 새 하드웨어 동작 시험은 수행하지 않았습니다.** 기존 실기 이력과 새 빌드 결과를 동일한 시험으로 보지 않습니다.

## 기존 실기에서 확인한 것

- BNO08x/SH2 가속도 표본과 SSD1306 초기화.
- USB OOB 등록, 잘못된 OOB 거부, 저장된 owner/bond 복원, 보안 레벨 4 연결.
- 표준 연결형 CS와 RAS 거리 결과, 독립 비콘 수신, CS만 재시작하는 시험과 전체 재연결 시험.
- 드론·탐색기 앱의 프로그래밍과 전체 기록 범위 읽기 대조. 읽기 대조는 동작/정확도 시험과 별개입니다.
- 수신 유지 개선 직후 별도 60초 두 구간에서 정상 결과 59개/61개, 최대 결과 간격 1.147초/1.088초. 이는 무손실 또는 장기 안정성을 보장하지 않습니다.

## 보행 필터 실기

탐색기 새 이미지를 기록한 후 총 352,524바이트의 앱 영역 읽기 대조에 성공했습니다. 부팅한 실제 C 코드의 자체 시험에서 `WALK_FILTER_SELFTEST pass=1 failed_line=0`을 확인했습니다.

자체 시험에는 20→5m, 20→0m, 역방향 변화, 단발 튐, 소수 초 간격, 공백/밀린 표본, 잘못된 입력, 64비트 시각, 결정적 난수 1,000개 표본이 포함됩니다. 합성 값은 실제 OLED나 무선 거리 결과에 주입하지 않습니다.

| 실제 측정 구간 | 결과 |
| --- | --- |
| 유효 원값 | 42개, 약 41.002초 |
| 필터 출력 | 40개 — 초기 두 표본은 준비 상태 |
| 표본 간격 | 0.800~1.292초 |
| 원값 최대 연속 변화 | 8.488m |
| 같은 순간의 필터값 | 1.757→1.757m 유지 |
| 필터 최대 연속 변화 | 1.361m / 1초 |
| 연속 출력 39쌍의 속도 한도 위반 | 0회 (로그 반올림 허용 오차 0.002m) |

이 구간의 큰 튐은 중앙값 단계에서 억제됐고 속도 제한 강제 개입은 없었습니다. 2m/s 제한의 직접 검증은 보드 내 합성 시험으로 구분합니다. 실거리 기준이 없으므로 위의 튐 수치는 절대거리 오차를 측정한 수치가 아닙니다.

사용자가 새 필터 적용 후 OLED/LED가 동작하고 숫자가 덜 튄다고 확인했습니다. 이후 실제 거리와 약 7~10m 차이가 있는 것 같다고 보고했으며, 그 원인과 정확한 오차 분포는 아직 확인하지 않았습니다.

## 관찰된 한계

- 업로드 뒤 드론이 이전 연결 상태에 남아 새 연결이 정체한 사례가 있었습니다. 드론 일반 재시작 후 회수 상태와 인증이 복원됐습니다. 보행 필터가 이 연결 정체까지 해결한 것은 아닙니다.
- 필터 시험의 60초 USB 수집은 약 55초에 포트 소실로 중단됐습니다. 완료된 60초 시험으로 집계하지 않았습니다.
- 중앙값과 속도 제한은 표시를 안정화하지만 정확도를 보장하지 않습니다. IFFT 중심 기본 추정기의 거리 보정이 필요합니다.
- 충격 ≥3g는 실험용 의심 임계값입니다. 실제 추락 판정의 오탐·미탐 성능은 검증하지 않았습니다.
