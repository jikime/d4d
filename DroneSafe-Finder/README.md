# 드론안심이 · DroneSafe

**NUCODE 기반 드론 분실·회수 비콘과 휴대용 탐색기**

> 길 잃은 드론을, 다시 내 품으로.

NUCODE NU-54V DK(nRF54L15) 두 대를 이용한 실험용 프로젝트입니다. 드론에 장착한 **DroneSafe Beacon**이 충격 의심 이벤트를 감지하면 회수 모드로 전환하고, 등록된 **DroneSafe Finder**가 인증된 Bluetooth LE Channel Sounding으로 거리를 추정합니다.

현재 기준은 **Nordic nRF Connect SDK v3.4.1**입니다. 초기 Arduino 실험본이 아니라, 표준 연결형 Channel Sounding과 RAS를 사용하는 최신 소스를 하나로 정리했습니다.

## 현재 상태와 한계

- 드론: 충격 의심 감지, 수동 회수 전환, 재시작 후 회수 상태 복원, 명목 1초 독립 비콘 광고.
- 탐색기: 소유자 인증 후 명목 1초 거리 측정, SSD1306 OLED 정수 m 표시, 거리 단계 LED.
- 보행 필터: 최근 3개 중앙값 + 경과시간에 따른 최대 2.0m/s 변화 제한.
- 연결 복구: CS만 재시작하는 단계와 전체 연결 재인증 단계를 구분.
- 두 보드 빌드·업로드·읽기 대조 및 짧은 실기 시험 이력이 있습니다. 개인 PC/보드 식별자를 제거한 새 패키지도 2026-10-11에 두 역할의 clean build와 HEX 생성을 확인했습니다. 이번 패키지 검증에서는 실제 보드 업로드·등록을 수행하지 않았습니다.

**아직 실전 투입용으로 검증된 제품이 아닙니다.** 거리 미보정과 큰 원값 튐이 남아 있으며, 숫자가 안정적이어도 실제 거리가 정확하다는 뜻은 아닙니다. 사용자가 관찰한 약 7~10m 차이의 원인은 아직 확정하지 않았습니다. 충격 오탐률, 장거리·차폐 환경, 장기 연결 복원, 배터리 지속시간도 별도 검증이 필요합니다. [시험 이력과 제한](docs/VALIDATION.md)을 먼저 읽어 주세요.

## 하드웨어

| 구분 | 현재 실기 확인 구성 |
| --- | --- |
| 드론 비콘 | NU-54V DK / nRF54L15, QWIIC BNO08x 호환 SH2 IMU(주소 0x4B) |
| 탐색기 | NU-54V DK / nRF54L15, SSD1306 128×64 I2C OLED(주소 0x3C) |
| 전원 목표 | 드론 메인 전원과 독립적인 3.7V 220mAh LiPo — 배터리 운용 미검증 |
| 시리얼 | 보드 디버그 브리지 UART, 115200 8N1 |

현재 IMU 드라이버는 **BNO08x/SH2용**입니다. 초기 논의에 등장한 **LSM6DS3TR과 호환되는 드라이버가 아닙니다.** 같은 I2C 커넥터라고 센서를 임의 교체하면 안 됩니다. NU40(nRF52840)은 일반 BLE 탐지 용도로 검토할 수 있으나 이 프로젝트의 Channel Sounding 상대 장치가 아닙니다.

NU54 전용 보드 확장을 저장소에 포함했습니다. 빌드 타깃 `nrf54l15dk/nrf54l15/cpuapp/nu54dk`의 **`/nu54dk`를 생략하지 마세요.** 일반 Nordic DK나 XIAO 핀 설정을 대신 적용하지 않습니다.

## 저장소 구성

```text
drone/              비콘 펌웨어: 센서 감시, 회수 상태, 광고, CS reflector
searcher/           탐색기 펌웨어: 인증, CS initiator, 거리 필터
searcher/tests/     실제 C 거리 필터 자체 시험
common/             인증, USB 콘솔, IMU, OLED/LED, 등록·검증 도구
common/vendor/sh2/  SH2 드라이버와 원본 라이선스
board_root/         NUCODE 전용 Zephyr 보드 확장
docs/               Windows 개발, 보안, 실기 검증 안내
```

## 시작하기

1. [Windows 빌드·업로드 안내](docs/GETTING_STARTED.md)에 따라 NCS v3.4.1과 도구를 준비합니다.
2. 자신의 비콘/탐색기 USB UID와 COM 포트를 확인합니다. 업로드와 등록 스크립트에 직접 지정해야 합니다.
3. 각 역할을 빌드하고, 대상 보드와 HEX를 확인한 뒤 별도로 업로드합니다.
4. 신뢰할 수 있는 PC와 USB 연결로 두 장치를 소유자 쌍으로 등록합니다.
5. 비콘의 `b` 명령 또는 SW1로 수동 회수 시험부터 시작합니다. 충격 시험은 이후 단계입니다.

키·등록 덤프, 개인 PC 경로, 원시 USB 로그와 기존 빌드 HEX는 포함하지 않습니다. 빌드 시 새 이미지를 생성하며, GitHub 업로드 과정에서 실제 보드를 다시 프로그래밍하거나 재등록하지 않습니다. 재현성을 위해 기존 펌웨어 프로젝트명/콘솔 이름은 그대로 보존했습니다.

## 표시와 동작

- 비콘 감시 중: 사용자 LED 1→2→3→4. 충격 의심 시 4개 점멸. 회수 모드에서는 광고 완료에 맞춰 LED 1 점멸.
- 회수 모드는 명시적 재무장 전까지 시간 제한 없이 유지합니다. 전원·배터리 및 실제 무선 상태는 별개입니다.
- 탐색기 OLED는 정수 m를 표시합니다. 연결이 살아 있지만 새 측정이 늦으면 마지막 값과 AGE를, 연결이 끊기면 `- m`를 표시합니다.
- 거리 LED는 ≤10m: 1개, ≤5m: 2개, ≤3m: 3개, ≤1m: 4개입니다. 3초 이상 오래된 측정의 LED는 끕니다. **이 구간은 추정값 기준이며 실제 1m 이내를 보장하지 않습니다.**
- 처음 정상 측정 3개를 모으느라 명목 1초 주기에서 약 2초 준비 시간이 있습니다. 필터는 표시의 튐을 억제하지만 절대거리 오차를 교정하지 않으며 반응 지연을 추가합니다.
- 일반 광고, LE Coded PHY, Channel Sounding은 서로 다릅니다. 현재 연결/CS는 1M PHY이며 LE Coded PHY 장거리 시험을 완료한 구성이 아닙니다.

## 인증과 전력 목표

신뢰 USB를 통한 LE Secure Connections OOB 등록 후 단일 소유자 bond를 사용합니다. 거리 측정은 등록 상대와 Bluetooth 보안 레벨 4 인증·암호화가 확인된 뒤에만 허용합니다. **광고와 무선 전파의 존재를 숨기는 기능은 아닙니다.** 자세한 신뢰 범위는 [보안 안내](docs/SECURITY.md)를 참고하세요.

현재는 수신 유지와 관찰을 우선한 **1초 주기 USB 실험판**입니다. 220mAh의 사용 가능 용량을 176mAh로 보면 전체 평균전류 목표는 30일 약 244µA, 60일 약 122µA입니다. 이 목표를 달성했다고 검증하지 않았습니다. LED·OLED·IMU·레귤레이터·개발보드 회로를 포함해 배터리 입력에서 측정하고, 광고 전용과 CS 측정 모드를 따로 평가해야 합니다.
