# 기울기 출력·태그 크기 자동 보정·비행 준비 — 펌웨어 `-30`~`-34`

2026-10-10 밤, [지상 시험 보고서](2026-10-10-bench-approach-inav-test.md)(`-27`~`-29`) 다음 작업이다. 지상 시험에서 나온 문제를 고치고 다시 시험한 내용, 그리고 실제 비행 시험 전에 확인할 것을 정리한다. 보드에 올라간 버전은 `TAGVISION-20261010-34`다.

## 2. 바뀐 것

### 펌웨어

| 빌드 | 바뀐 점 |
|---|---|
| `-30` | **기울기 출력** (`out_tilt 1`, 기본). 가속도 `a = 1.5 × (목표 속도 − 실측 속도)`(상한 50cm/s²) → 기울기 `atan(a/g)` → INAV 곡선 역변환 → µs(상한 200µs, 변화율 400µs/s). INAV 곡선은 소스대로 `rcCommand = rcLookup(applyDeadbandRescaled(µs−1500), rc_expo)`, `기울기 = rcCommand/500 × 45°`. **FC의 `rc_expo`·`deadband`를 직접 읽어** 쓴다(이 FC: 80, 2). 피드포워드는 지연이 있는 기체 모델 시험에서 오히려 지나침(13.5cm/s)을 만들어 0으로 둠 |
| `-31` | 카메라 노출 명령 `exp` / `exp auto [ae]` / `exp fast`(20, 게인 8) / `exp <노출> [게인]` |
| `-32` | `-30`에서 생긴 회귀 수정: FC 설정 질의가 마스크 질의를 밀어내 `mask_unknown` 고장이 잦았음 → 질의 5번 중 4번은 마스크, 마스크 유효 시간 10초 |
| `-33` | **태그 크기 자동 보정** (`src/tag_size_cal.h`, `tagcal` 명령). 높이 상한 기본 300cm. `info`에 재부팅 원인(`reset`)·태스크 스택 여유 |
| `-34` | 보정은 마지막 수렴값 유지(`held`). `approach` 줄에 `fc_rp`(FC가 받은 롤·피치)·`fc_rp_age_ms` |

**태그 크기 자동 보정 (`-33`):** 카메라가 아래를 보고 바닥과 나란하면, 바닥에 놓인 물체는 화면 어디에 있든 `한 변(mm) = 화면 한 변(px) × 높이(cm) / fx × 10`이다(fx ≈ 615px, 수평 화각 55°). 아래 조건을 모두 만족하는 프레임만 표본으로 쓴다. 최근 15개 표본의 중앙값을 쓰고, 표본이 8개 이상이며 퍼짐(중앙값 절대편차 / 중앙값)이 6% 이하이면 그 값을 쓴다.

| 표본 조건 | 값 |
|---|---|
| 높이 출처 | FC 거리센서, 25~300cm (시뮬레이션 높이 제외) |
| 기체 자세 | FC 자세가 1.2초 안에 들어왔고 롤·피치 각각 6° 이하 |
| 카메라 서보 | 틸트 3° 미만, 정지 상태 |
| 태그 | 인식 여유(margin) 40 이상, 네 꼭짓점이 화면 가장자리에서 8px 이상 안쪽 |
| 표본 값 | 10~2000mm (그 밖은 버림) |

명령은 `tagcal`(상태), `tagcal on|off|reset`, `tagcal save <id>`(수렴값을 NVS에 저장)다. 태그는 **바닥에 놓여 있어야** 맞다. 손에 든 태그는 높이와 태그 거리가 달라 틀린 값이 나온다.

`test/approach_host_test.cpp`에 INAV 곡선 왕복, 기울기 출력(a = 15cm/s² → 약 49µs, 상한 50 → 약 130µs), 지연이 있는 1차원 기체 모델(expo 80, 자세 시정수 0.33초, 카메라 4fps·지연 0.3초, 광류 10Hz·지연 0.1초)을 추가했다. 최대 속도는 10.83cm/s이고 지나침은 0이다. `test/tag_size_cal_host_test.cpp`는 표본 계산, 수렴, 튀는 값, 오래된 표본 밀어내기, 마지막 수렴값 유지를 시험한다. 모두 통과했다.

## 3. FC 설정 복구 — 거리센서·광류가 `NONE`이었다

- **증상:** 보드가 FC에서 받는 높이가 0, 광류도 0이었다. 보드로 FC 설정을 읽어 보니 `rangefinder_hardware = NONE`, `opflow_hardware = NONE`이었다. 오전 백업(`fc-info/diff_all_20261010.txt`)에는 둘 다 `MSP`다. 누가 언제 바꿨는지는 모른다.
- **복구 (사용자 승인):** 보드 경유 MSP로 바꿨다.
  - `MSP2_COMMON_SET_SETTING`(0x1004)으로 `rangefinder_hardware = 3`(MSP), `opflow_hardware = 2`(MSP). 번호는 INAV 9.1 `settings.yaml` 순서다.
  - 디스아밍을 확인한 뒤 `MSP_EEPROM_WRITE`(250)로 저장했다.
- **저장 직후 FC가 UART5에서 응답을 멈췄다.** 보드가 940번 보내도 응답이 0이었다. FC 전원을 껐다 켜자 돌아왔다(원인 불명).
  - 재시작 뒤 두 설정은 저장된 값 그대로였고, 센서 상태(`MSP_SENSOR_STATUS` 151)에서 거리센서 1, 광류 1(정상)이었다.
  - `rc_expo 80`, `deadband 2`, 마스크 7이 그대로라 설정이 초기화되지 않았음을 확인했다.
- 센서 종류 설정은 FC가 켜질 때만 적용되므로, 바꾼 뒤에는 FC를 재시작해야 한다.

## 4. 시험 결과

시험 조건: 프로펠러 없음, FC 디스아밍, 배터리 3S 12.1V, CH6 1000(AUTO), 마스크 7, `approach bench`(높이 = 거리센서, 거리센서가 무효면 태그 거리, 속도 = 카메라), `exp fast`. 기체를 손에 들고 바닥의 태그(ID 1) 위에서 움직였다.

### 4.1 기울기 출력 (`-30`)

- 기체가 가만히 있고 태그가 25cm 이상 떨어졌을 때 명령은 ±49µs다(목표 10cm/s → 15cm/s² → 0.88°). 예전 µs 출력은 ±16~24µs였다.
- 손으로 움직일 때는 최대 ±130µs가 나왔다(가속도 상한 50cm/s² ≈ 2.9°).
- 이 FC는 `rc_expo 80`이라 중앙 근처 스틱 변위가 약 0.2배로 약해진다. 그래서 같은 기울기를 만들려면 µs가 커야 한다. 예전 상한 80µs는 실제로 약 1.6°였다.

### 4.2 태그 크기 자동 보정 (`-33`, 270초 기록)

| 시각 | 화면 한 변 | 쓴 크기 | 표본 수·퍼짐 | 태그 거리 | 거리센서 높이 |
|---|---|---|---|---|---|
| 157.5초 (보정 전) | 108px | 200mm (설정) | 0 | **113cm** | 47cm |
| 166.2초 | 174px | **86mm (자동)** | 11개 · 1.7% | 31cm | 약 30cm |
| 174~196초 | 119~147px | 86~89mm | 15개 · 1.4~3.7% | 37~45cm | 40~46cm |
| 207.5초 | 147px | **200mm (설정으로 되돌아감)** | 15개 · 8% | 84cm | 약 40cm |
| 211~219초 | 196~245px | 80mm | 15개 · 2.7% | 20~33cm | — |

- 보정 전에는 200mm 가정 때문에 거리와 위치 오차가 약 2.3배 크게 계산됐다. 보정 뒤에는 거리센서 높이와 맞는다.
- 207.5초처럼 움직이는 중에 퍼짐이 6%를 넘으면 설정값으로 돌아가 거리가 튀었다 → `-34`에서 마지막 수렴값을 유지하도록 고쳤다.
- 수렴값이 86~89mm와 80mm 두 무리로 나뉜다. 태그 ID 1을 자로 재서 맞는 값을 `tagcal save 1` 또는 `size 1 <mm>`로 저장해야 한다(미완).
- 보정값은 RAM에만 있어 재부팅하면 처음부터 다시 모은다. 태그 위에서 몇 초 들고 있으면 다시 수렴한다.

### 4.3 INAV 값이 움직이는 조건 (`-34`, 192초 기록, 접근 보고 937개)

`approach.h`의 판정 순서다. 하나라도 안 맞으면 보드는 롤·피치를 1500으로 돌린다(변화율 400µs/s).

| 순서 | 조건 | 안 맞으면 (`fault`·상태) |
|---|---|---|
| 1 | 접근 모드 `on`, CH6 AUTO, 킬 아님, FC 마스크 확인·정상 | `disabled` · `manual_authority` · `kill` · `mask_unknown` · `mask` |
| 2 | 높이 20~300cm, 0.3초 안에 갱신 | `height` |
| 3 | 속도 측정값이 신선함. 지상 시험은 카메라 속도라 **태그를 연속 2장 인식**해야 함, 비행은 광류 품질 40 이상 | `flow` |
| 4 | 측정 속도 60cm/s 이하 | `velocity` |
| 5 | 태그를 지금 인식 중 (`tag_stale_ms` 안: 기본 0.6초, 이 시험은 1초) | `tag_lost` (`lost_neutral 1`: 즉시 중립) |
| 6 | 태그가 중심에서 5cm 넘게 떨어짐 | 정지 반경 → 중립 |
| 7 | "도착"이 아님 (5cm 안·3cm/s 이하로 2초 머물면 도착. 5cm 밖으로 벗어나야 풀림) | `ARRIVED` → 중립 |

조건을 모두 만족하면 목표 속도는 5cm에서 0, 25cm 이상에서 10cm/s이고 그 사이는 거리에 비례한다. 명령은 `1.5 × (목표 속도 − 측정 속도)`에서 나온다. 그래서 기체를 **가만히 들고 있으면** 명령이 계속 나가고(10cm에서 약 20µs, 25cm 이상에서 약 49µs), 손으로 태그 쪽으로 움직이면 그 속도만큼 줄어든다.

| 기록 중 비율 | 상태 | INAV |
|---|---|---|
| 58% | `FAULT/height` — 기체를 바닥에 내려놓음(2~4cm) | 1500 |
| 17% | 태그가 중심 5cm 안 또는 `ARRIVED` | 1500 |
| 11% | `FAULT/flow` — 태그 미인식, 또는 막 다시 인식해 속도가 아직 없음 | 1500 |
| **14%** | **`ARRIVING` · 태그 인식 · 중심에서 5~25cm** | **움직임** |

- 보드 명령과 INAV 값이 어긋난 13번은 모두 명령이 켜지거나 꺼지는 순간이었다(0.1~0.2초 지연).
- 앞선 270초 기록에서도 보드 명령이 0이 아닌 78번 중 77번은 INAV가 1500에서 벗어났다. 예: 보드 +41/+41µs → INAV 1541/1541, 피치 −130µs → 1420.
- **즉 INAV 값은 태그가 화면에 보이는 동안에만 바뀐다.** 높이별로 보이는 바닥 범위는 수평 화각 55° 기준으로 높이 40cm에서 약 ±21×±16cm, 60cm에서 ±31×±23cm, 100cm에서 ±52×±39cm다. 네 꼭짓점이 다 보여야 하므로 실제로는 태그 반 변만큼 좁다.

### 4.4 광류 교차 확인 — **미검증**

비행에서는 속도를 FC 광류로 잰다. 지상 시험 기록에서 광류 속도(`v_of`)와 카메라 속도(`v_tag`)를 비교했다.

| 기록 | 비교 표본 | 오른쪽 상관 | 앞 상관 | 광류 품질 중앙값 |
|---|---|---|---|---|
| `-33` 270초 | 227 | −0.25 | +0.27 | 7 |
| `-34` 192초 | 288 | −0.15 | −0.09 | 25 |
| `-34` 재시작 후 | 219 | −0.23 | +0.17 | 10 |

- 상관이 0에 가깝고 부호도 섞여 있어 **광류 축·부호를 확인하지 못했다.**
- 광류 품질도 비행 조건(`flow_min_q 40`)보다 낮다. 이대로 비행 모드를 켜면 대부분 `FAULT/flow`가 되어 중립(1500)으로 남는다. 안전 쪽이지만 제어도 안 된다.
- 원인 후보는 세 가지다. 손으로 들어 기울어지면서 생긴 회전 성분, 낮은 높이·조명·바닥 무늬, 그리고 이 비교 방식이다(카메라 속도는 5Hz에 잡음이 크다).

## 5. 문제와 원인

| 문제 | 원인 | 대응 |
|---|---|---|
| FC 거리센서·광류 `NONE` | 알 수 없음 (오전 백업은 `MSP`) | 3절대로 복구. 비행 전 `fcmsp 151`로 센서 상태 확인 |
| EEPROM 저장 직후 FC가 응답 없음 | 알 수 없음 | FC 전원 재시작으로 복구. 설정은 보존됨 |
| USB 시리얼이 0바이트로 멈춤 (또) | FC 배터리를 끼우고 뺄 때 함께 멈춤. 이중 전원 또는 순간 전압 변동으로 추정 | USB-C를 뽑았다 꽂으면 복구. 그동안은 BLE로 상태 확인 가능(보드는 계속 동작) |
| BLE 카메라 창이 매우 느림 (사진 한 장 약 10초) | 사진(약 35KB, base64)이 BLE로 초당 약 3KB밖에 안 나감. 그동안 보드 출력이 막혀 상태 줄도 멈춤 | 화면은 USB로 본다. BLE 전용 작은 사진은 남은 과제 |
| `-33`에서 약 151초에 재부팅 1회 (`reset: panic`) | 원인 미확인. 태그 처리 중은 아니었음 | 카메라 창이 `Guru`·`Backtrace` 줄을 기록하도록 함. 다시 나면 `firmware.elf`로 주소 해석 |
| 재부팅하면 지상 시험 설정·크기 보정이 사라짐 | 접근 모드·파라미터·보정값은 RAM. USB 포트를 열 때마다 보드가 재부팅됨 | 카메라 창 `--init`이 재부팅마다 다시 보냄. 크기는 `tagcal save`로 NVS 저장 |

## 6. 비행 시험 — 펌웨어 업데이트가 필요한가

**첫 비행(관찰 비행)은 지금 펌웨어(`-34`) 그대로 할 수 있다.** 보드는 켜질 때 비행 입력(거리센서·광류)과 `shadow` 모드로 시작한다. `shadow`는 계산하고 기록만 하며 FC에는 1500을 보낸다. **보드가 실제로 조종하는 비행(`approach on`)은 4.4절 광류 검증이 먼저**이고, 결과에 따라 펌웨어 기본값을 고쳐 올려야 할 가능성이 크다.

| 할 일 | 펌웨어 업데이트 | 비고 |
|---|---|---|
| 태그 ID 1 실측 → `tagcal save 1` 또는 `size 1 <mm>` | 필요 없음 (NVS) | 86~89mm인지 80mm인지 결정 |
| 광류 축·부호·품질 확인 | 확인만이면 필요 없음 | 관찰 비행 기록의 `v_of` ↔ `v_tag`, `flow_q` |
| 광류 부호·`flow_min_q` 변경 | **바꿔야 하면 필요** | BLE `approach set flow_swap/flow_fwd_sign/flow_right_sign/flow_min_q`로도 되지만 재부팅하면 사라진다 → 확인된 값을 `approach.h` 기본값으로 굳혀 올린다 |
| 기울기 보정(`att_comp`) 부호 확인 후 켜기 | 기본값을 바꾸려면 필요 | 1m에서 2.2° 기울면 약 3.8cm 밀려 보임 (정지 반경 5cm와 비슷한 크기) |
| 보드 `kill`을 FC에 반영 | 필요 없음 (FC 마스크 7 → 71, 승인 필요) | 지금은 조종기 ARM 스위치가 정지 수단 |

### 순서

1. **INAV 모드: ANGLE + ALTHOLD.** 보드는 스틱 µs를 기울기로 계산한다(ANGLE 기준). POSHOLD에서는 스틱이 속도 명령이라 크기가 맞지 않는다. 높이는 보드가 조종하지 않는다(마스크 7에 스로틀 없음). INAV ALTHOLD나 조종자가 맡는다.
2. **전원:** 비행 중에는 USB를 빼고 FC 5V(빨간 선)로 보드를 켠다. USB와 FC 5V를 동시에 넣지 않는다.
3. **관찰 비행** (보드 기본값 그대로, **CH6 MANUAL 유지**).
   - `shadow`에서 CH6를 AUTO로 두면 FC가 보드 값 1500을 써서 조종기 롤·피치가 먹지 않는다.
   - 태그 위 50~100cm에서 호버링하고, 태그 쪽으로 천천히 오가며 BLE로 기록한다.
     ```bash
     uv run --no-project --with bleak --with pyserial python3 tools/tag_monitor.py --ble --raw > flight1.jsonl
     ```
   - 확인할 것:
     - 높이가 유효한가(`height_valid`)
     - 광류 품질이 40 이상인가(`flow_q`)
     - `v_of`가 실제 이동 방향과 맞는가
     - 태그 크기가 수렴하는가
     - `shadow`에서 계산된 `roll_us`·`pitch_us`가 태그 쪽을 향하는가
4. 3의 결과로 광류·자세 보정 값을 정하고, 필요하면 펌웨어 기본값을 고쳐 올린다.
5. **제어 비행:** BLE로 `approach on`을 보낸다(`tag_monitor.py --ble --raw --cmd "approach on"`). 50~80cm 높이에서 태그를 약 20cm 옆에 두고 CH6를 AUTO로 잠깐 바꾼다. 10cm/s 이하로 다가가 5cm 안에서 멈추는지 본다. 이상하면 즉시 CH6 MANUAL로 돌린다.
6. 태그를 놓치면 보드는 1500으로 돌아간다(`lost_neutral 1`). 태그를 찾으러 움직이는 기능은 없다.
