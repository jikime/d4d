## 실기체 영상 중심 관제·스로틀 모니터 (2026-10-11)

- **기체 연결**의 중앙 화면은 실제 Wi-Fi 카메라다. 실제 센서로 동기화한 3D 자세를 작은 보조 화면으로 유지하며, **실제 영상 / 3D 자세**로 중앙 화면을 교환한다. 보조 화면 숨김, 영상 집중 보기, Esc로 대시보드 복원을 지원한다. 모바일에서는 영상 다음에 계측 패널을 배치한다.
- 왼쪽에는 조종기 스로틀 입력과 FC 모터 출력 평균을 각각 µs·막대로 표시하고, 최근 15/30/60초 변화 그래프를 제공한다. 오른쪽에는 모터 4개, RC 채널, 자세·높이, 전압·전류를 함께 표시한다. 1000–2000µs의 표시 비율은 추력이나 실제 RPM이 아니다.
- 스로틀은 최신 `rc_throttle`, 또는 FC 정규 순서 `fc_rc[3]`에서 읽는다. AETR 송신 배열의 `out[2]`나 `thr_slot_us`는 스로틀 계측으로 쓰지 않는다. 새 표본만 기록하며 연결 세션 변경은 기록을 초기화한다. 수신 공백은 그래프에서 연결하지 않고 오래된 값은 `—`로 표시한다.
- 현재 펌웨어는 `throttle_ctrl=false`이고 스로틀 조절 권한은 실제 조종기에 있다. **웹 막대는 계측 표시이며 실제 출력을 바꾸는 슬라이더가 아니다.** 펌웨어·RC override mask·아밍 설정은 변경하지 않았다.
- 사진 요청 시각이 아니라 **브라우저가 로드한 사진의 실제 수신 시각**으로 영상 지연을 표시한다. 영상이 멈추면 마지막 사진과 지연 안내를 남기고 실시간 영상으로 표시하지 않는다. 5초간 SSE 보고가 없으면 브라우저가 상태 스트림을 다시 연결한다.
- 직접 연결은 확인된 `TAGVISION-20261011-38` 이상에서 `snap stream 200`으로 연속 사진을 수신한다. `SNAPB` / `SNAPC`의 길이 구분 바이너리 JPEG와 중간에 섞이는 상태 보고를 처리한다. 이전 지원 펌웨어는 `snap small`을 유지한다. 기존 카메라 뷰어가 연결돼 있으면 계속 로그·사진을 공유하며 별도 소켓을 만들지 않는다.
- 웹 테스트 167개, 서버 테스트 30개, TypeScript·Vite 빌드 통과. 바이너리 안의 줄바꿈·가짜 JSON, 잘린 조각, 과대 크기, 구형 펌웨어 fallback과 RC 채널 순서·데이터 만료를 검사했다. 1800×1009 / 390×844에서 화면 전환·집중 보기·보조 화면 숨김·기록 구간 선택을 확인했다.
- 실제 수신에서 스로틀 **1516µs → 51.6%**, 모터 출력 평균 **1477 → 1474µs**, 높이 **1.23 → 1.21m**와 640×480 카메라 갱신을 확인했다. 보조 3D는 기체를 가까이 추적해 고도가 바뀌어도 화면 안에 유지한다. 웹에서 비행 출력을 보내는 시험은 하지 않았다.

## Wi-Fi 실기체 움직임 관측 (2026-10-11)

- 상단 **기체 연결**은 실제 카메라·계측값을 사용하는 3D 관측 화면을 연다. AprilTag 기반 실제 경로 실행은 이번 단계에서 제외한다. **훈련 화면**으로 기존 시뮬레이터에 돌아간다.
- 확인된 연결은 `D4D_Hacker_01` 망의 `192.168.0.151:3333`이다. 보드 주소는 화면에서 바꾸거나 서버의 `D4D_BOARD_HOST`로 지정한다. SSID는 보드 IP 주소와 구분한다.
- 로컬 백엔드가 TCP 스트림을 하나 소유하고, 브라우저에는 SSE 상태와 JPEG를 전달한다. 분할 JSON·사진 사이에 섞인 상태 보고·불완전한 JPEG를 처리하며, 마지막 수신 시각을 표시한다.
- 프로젝트의 `tools/cam_view.py --wifi ... --ap-log ... --dump ...`가 같은 보드에 연결돼 있으면 기존 뷰어의 실측 로그와 사진을 공유한다. 이미 열린 TCP 연결을 빼앗거나 뷰어를 종료하지 않는다. 뷰어 종료 후에는 직접 수신으로 전환하고, 새 연결마다 상대 이동 원점을 초기화한다. 로그·사진 파일 경로는 브라우저에 노출하지 않는다.
- 직접 수신의 보드 명령은 `info`, `wifi`, `fcmsp 108`(자세 조회), `snap small`, 지원 펌웨어의 `snap stream 200`으로 제한한다. 사진 전송이 검출을 막는 이전 펌웨어에는 자동 사진 요청을 보내지 않는다. 임의 명령·아밍·스로틀·경로 업로드 API는 없다. 기존 펌웨어와 RC 권한 설정은 수정하지 않았다.
- 롤·피치·방위각·거리센서 높이를 3D 자세와 높이에 반영한다. 프로펠러 시각화는 FC 모터 출력값을 따른다. 모터 µs는 실제 RPM으로 표시하지 않는다. Wi-Fi 신호, 전압·전류, 조종기 채널, 조종 권한도 실측 보고로 표시한다.
- 수평 위치는 광류 품질 40 이상, 유효한 실제 높이 20cm 이상, 최신 방위각이 모두 있을 때 유효한 속도 표본 사이만 적분한 **상대 위치 추정**이다. 절대 위치·계획 경로로 가장하지 않는다. 누락 표본, 긴 수신 공백, 낮은 품질, 시험 센서값은 적분하지 않는다. 기존 뷰어가 방위각을 기록하지 않으면 미수신으로 표시한다.
- 연결이 끊기면 마지막 3D 자세·위치는 보존하고 오래된 지표·모터 애니메이션을 만료시킨다. 사진 파일에 오버레이만 다시 저장돼도 새 카메라 프레임으로 취급하지 않는다. **현재 위치를 원점으로**는 화면의 상대 좌표만 초기화한다.
- 검증: 실제 보드 영상·자세·높이·전압·모터 출력 수신, 기존 뷰어 공유 및 직접 수신 전환, 카메라 확대와 3D 확대를 확인했다. TCP 모의 보드와 분할 프레임·명령 허용목록·로컬 API·공유 뷰어 테스트를 추가했다. 실제 아밍·이륙·조종 명령은 보내지 않았다.

## 주요 지점 AprilTag·계획 경로 비행 (2026-10-11)

### 태그 배치와 비행 흐름

- 실제 표지는 시나리오에 등록된 주요 지점에만 배치한다. 청솔 훈련장에는 **이착륙장·연병장·막사 북측·관제동 앞·정비고 진입로·보급창고 앞의 6개 태그**를 둔다. 경로 중간에 연결 태그를 자동 생성하지 않는다. 건물 회피를 위한 경유점은 지도상의 좌표이며 물리 태그가 아니다.
- 지점 사이는 계획 경로와 시뮬레이터의 자기 위치를 이용해 이동한다. 태그가 카메라 시야 밖에 있는 것은 정상적인 이동 상태다. 계획 속도·순항 속도·가속도 제한을 적용하고, 목적지에 가까워지면 감속해 태그를 찾는다.
- 해당 목적지 ID를 카메라에서 읽으면 **계획 경로 이동 → AprilTag 영상 정렬 → 연속 인식 확인 → 체류 → 다음 지점**으로 진행한다. 영상 중심·실제 태그 크기·촬영 자세에서 얻은 오차로 접근한다. 지도 좌표에 도착했다는 이유만으로 태그 방문을 완료하지 않는다.
- 목적지 태그가 가려졌거나 다른 ID이면 위치를 유지하며 재인식을 기다린다. 올바른 ID가 다시 보이면 별도의 시작 명령 없이 이어간다. 일반 경유점이나 태그가 지정되지 않은 좌표 지점은 계획대로 통과·체류하며, 태그 인식 실적으로 집계하지 않는다.
- 대시보드와 카메라에는 **계획 경로 이동 / 목적지 태그 탐색 / AprilTag 영상 정렬**을 구별해 표시한다. 기존 방문 순서·회피 경로·귀환 착륙과 키보드 조종을 유지한다. 수동 조종 후 자동 모드로 돌아오면 현재 위치에서 회피 경로를 계산해 남은 계획에 합류한다.

### 실제 픽셀 인식과 정지 처리

하향 카메라의 원본 320×240 RGBA 영상을 Web Worker에 전달해 **AprilTag 3 WASM 디코더**로 읽는다. 디코더에는 이미지 외에 예상 ID나 지도 좌표를 전달하지 않는다. 사각형·ID 자막은 인식 후 별도로 그린다. 대시보드를 숨기거나 모바일에서 카메라 패널이 숨겨져도 영상 입력은 계속된다. `observeTag`는 단위 시험의 시야 예측에만 사용한다.

잘못된 ID, 낮은 신뢰도, 잘린 태그, 700ms 이상 지난 프레임을 확인에서 제외한다. 이전 비행 세션·반복 프레임으로 확인 시간을 채울 수 없다. 임무 태그는 최소 3프레임과 설정된 안정화 시간을 모두 충족해야 방문 처리한다. 태그 판의 높이는 0.061m로 바닥 장식 선 상단 0.056m보다 높게 유지한다.

창의 `blur`는 자동 비행을 멈추지 않는다. 백그라운드 탭에서는 비행 시간을 멈추고, 돌아왔을 때 직전에 자동 비행 중이던 세션만 재개한다. 사용자가 누른 일시정지, 수동 조종, 임무 편집은 자동으로 재개하지 않는다. 카메라 스트림 자체가 끊긴 경우에는 위치를 유지하고 원인을 표시한다. 태그가 없는 이동 구간에서 정상 카메라 영상이 계속 들어오는 상황과 구분한다.

### 디코더 출처와 모델 범위

[AprilRobotics 공식 프로젝트](https://github.com/AprilRobotics/apriltag)에서 소개하는 [AliAlimohamad의 WASM 바인딩](https://github.com/AliAlimohamad/apriltag-js)을 사용한다. 배포 파일은 커밋 `4359086c430e44342098a464c359aacf00cf6bc8`에 고정했으며, `web/public/vendor/apriltag`에 JavaScript·WASM·BSD 라이선스·NOTICE·C 래퍼·빌드 스크립트와 SHA-256 목록을 보관한다. 해당 바인딩의 AprilTag 서브모듈 커밋은 `fb2a4096ec5f84b9ec18e501dfa129ffeaaf774e`이다. 재현하려면 위 커밋을 서브모듈과 함께 체크아웃하고 Emscripten 환경에서 `wasm-build/compile.bat` 절차를 따른다. C 검출 알고리즘이나 배포 바이너리는 수정하지 않았다.

카메라는 3D 훈련 장면에서 렌더링하며 자세는 수평을 유지하는 하향 짐벌 모델이다. 지점 사이의 자기 위치는 시뮬레이터 상태를 사용하고, 목적지 정렬은 실제 영상의 측정 오차를 사용한다. 실기기 GPS·VIO·SLAM, 실제 비행 제어기, 강화학습 또는 검증된 공력 모델을 구현했다는 의미는 아니다. 태그 안에는 ID만 있으며 임무 순서와 동작은 계획과 등록표에서 조회한다.

### 주요 지점 비행 검증

- 단위·회귀 검사 **10개 파일, 151개 통과**. TypeScript·Vite 빌드 통과. 기존 3D 공유 청크 크기 경고는 남는다.
- 브라우저의 실제 3D 메시를 검사해 `apriltag-1`부터 `apriltag-6`까지 **6개만 존재**함을 확인했다. 기본 경로는 7회의 주요 지점 확인과 4개의 태그 없는 회피 경유점으로 구성된다.
- 실제 카메라 픽셀 디코딩으로 **1 → 2 → 3 → 4 → 5 → 6 → 1** 확인·귀환 착륙에 성공했다. 검증 실행은 모델 시간 약 **98.38초**, 이동 거리 **107.78m**, 귀환 오차 약 **2.7cm**, 착륙 고도 **0.22m**였다.
- 지점 사이에 검출 태그가 0개인 상태에서 약 **2.12m/s**로 계획 경로를 따라 진행했다. 목적지 TAG 2의 실제 그림을 코드 3으로 바꾸면 TAG 1까지만 방문 처리하고 TAG 2에서 14초 이상 대기했다.
- TAG 2 그림을 복구하면서 실제 표지 메시만 30cm 이동하고 계획 좌표는 유지했다. 자동 재인식 후 옮긴 표지에 약 **3.3cm** 오차로 정렬·확인했다. 시험 후 표지 메시 위치와 그림은 복원했다.

## shadcn/ui 폼·Pretendard·비행 기체 표시 (2026-10-11)

통합 관제 작업을 `44cebb3`으로 먼저 커밋한 뒤 진행했다.

- 메인 임무 선택·편집, 관제 조정, 정밀 접근 시험, 키보드 비행, 기체 연결 패널의 기본 폼을 shadcn/ui의 `Select`, `Slider`, `Input`, `Textarea`, `Switch`, `Checkbox`로 교체했다. 수정안 제출 폼은 `Field`, `FieldLabel`, `FieldDescription`, `Button`을 사용한다. 의미 있는 HTML `form`과 기존 제출·검증 동작은 유지한다.
- [공식 Vite 설치 안내](https://ui.shadcn.com/docs/installation/vite)에 맞춰 별칭·레지스트리 설정과 Tailwind 4 색상 토큰을 추가했다. 선택 팝업은 포털로 표시하며 모달 위에서도 잘리지 않는다. 공통 컨트롤에 검정·국방색, 키보드 초점, 비활성 상태를 적용했다.
- 메뉴·슬라이더·입력창·스위치의 키보드 조작은 비행 입력과 분리했다. 포털의 Esc는 메뉴만 닫으며, 폼에 초점을 옮기면 누르고 있던 조종 입력을 해제한다. 일반 비행 버튼을 누른 뒤에는 비행 단축키를 계속 사용할 수 있고 Space/Enter는 버튼의 기본 동작을 유지한다.
- [Pretendard 공식 배포본](https://github.com/orioncactus/pretendard)의 v1.3.9 가변 WOFF2를 `web/public/fonts`에 포함했다. SIL OFL 라이선스도 함께 보존했다. UI·계측 숫자·캔버스 라벨·훈련장 간판에 적용하며 외부 폰트 CDN을 사용하지 않는다.
- 자동 비행 시작·재개 시 근접 추적으로 전환한다. 기존 상세 3D 기체의 프로펠러 회전, 항법등, 자세 변화, 짐벌을 그대로 보여주며 추적 화면에서는 기체 이름표를 제거했다. 태그 이름표도 목표 지점 위주로 정리했다.

## 통합 3D 훈련 관제·AprilTag 순환 비행 (2026-10-10)

이 절은 아래의 이전 화면 구성 설명을 대체한다. 첫 화면이 곧 3D 관제 화면이며, 상단 **조종기 보기**는 같은 장면을 조종기 LCD 안에 표시한다. 별도의 기체나 경로를 만들지 않는다.

- 기본 시나리오는 가상의 **청솔 훈련장**이다. 48×36m 부지의 막사·관제동·정비고·보급창고, 도로·연병장·펜스·가로등·외곽 수목을 코드로 구성했다. 건물 장애물, 도면, 미니맵, 경로 계산, 3D가 동일한 좌표와 축척을 사용한다. 기존 생성형 지면 재질은 재사용했으며 이미지에서 복원한 3D라고 표시하지 않는다.
- 기본 코스는 이착륙장 → 연병장 → 막사 북측 → 관제동 앞 → 정비고 진입로 → 보급창고 앞 → 출발점 착륙이다. 장애물을 피하는 A* 경유점을 생성하고, 서버에서 계획을 생성하면 그 계획의 태그 ID·좌표·고도·속도·체류 시간을 불러온다. 충돌하거나 경계 밖인 계획은 시작을 막고 이유를 표시한다.
- 비행 상태는 `이륙 → 경로 비행 → 감속 접근 → 태그 탐색 → 정밀 정렬 → 연속 인식 확인 → 체류 → 다음 지점 → 귀환 착륙`으로 진행한다. 수평 오차, 수평·수직 속도, 관측 고도, 연속 검출 시간이 모두 충족되어야 태그를 방문 처리한다. 태그를 가리면 확인되지 않으며, 위치를 유지하다가 다시 읽히면 자동으로 이어간다.
- 자동 비행 세밀 조정에서 순항 속도, 관측 고도, 정렬 허용오차, 인식 유지 시간, 가속도 한계, 바람 외란을 바꾼다. 설정은 실제 훈련 모델에 반영되고 인식 누적을 다시 시작한다. 계획에 지정된 속도는 해당 구간의 추가 상한이다.
- 전방 카메라와 하향 태그 카메라는 같은 Three.js 장면의 기체 위치·방위각에서 렌더링한다. 하향 영상은 320×240, 가로 화각 55°이며 태그 테두리·중심 오차·검색선·검출 상태를 영상에 겹친다. 각각 확대해서 볼 수 있다.
- 관제 대시보드는 실제 모델의 위치·속도·자세·상승 속도·이동 거리·배터리·전압·전류·통신 품질·정렬 오차·비행 사건을 갱신한다. 배터리와 통신 값은 명시된 훈련용 추정 모델이다. 건물·경계 접근에서는 정지하며, 통신 두절 정책과 배터리 부족도 호버에 반영한다.
- 비행 경험은 태그별 탐색 시간·최종 오차·방문 수와 재탐색 실패 구역을 같은 지도에 대해 로컬 저장한다. 착륙 또는 초기화 후 **기록된 경험 적용**으로 후속 비행의 접근 설정과 기본 경로 비용에 반영한다. 실패 구역이 없는 기록 때문에 불필요한 경유점이 늘어나지 않는다. 신경망 학습이나 강화학습은 구현하지 않았으며, 서버의 계획 순서는 경험 적용으로 바꾸지 않는다.

- 기존 임무 편집·계획 검증·승인·산출물·정밀 접근 각본은 유지한다. **임무 패널 → 편집 → 도면에서 태그 배치**에서 노드를 편집하면 같은 3D에 반영된다. **정밀 접근 시험**은 기존 여섯 제어기 각본을 연다.

## 대형 LCD·키보드 직접 조종·경유점 비행 (2026-10-10)

이전 관제·조종기 작업을 `ce8cb10`으로 먼저 커밋한 뒤 진행했다. 메인 페이지의 시뮬레이터는 키보드 비행으로 열리고, 실기기 패널의 접근 시뮬레이션은 기존 정밀 접근 시험으로 열린다. 두 화면 사이의 전환 버튼도 제공한다.

- 조종기 v2는 손잡이·상하 베젤·안테나 공간을 줄여 LCD를 본체 폭 약 78%, 높이 약 81%로 확대했다. 원본 이미지를 보존하고 새 [생성 자산과 프롬프트](../web/public/controller/GENERATED_ASSET.md)를 기록했다.
- `W/S`는 상승·하강, `A/D`는 기체 좌·우 회전, 방향키는 기체 기준 전후·좌우 이동이다. 여러 키를 동시에 유지할 수 있고, 반대 키는 상쇄하며 수평 대각선 입력은 속도가 더 빨라지지 않도록 정규화한다. 가상 스틱도 동일한 기체 입력에 연결한다.
- `Space`는 제동, `P`는 일시정지·재개, `R`은 출발 위치 초기화, `H`는 대시보드 표시 전환이다. 키를 놓으면 감속 후 호버하며 입력 필드에 포커스가 가면 조종 키를 해제한다. 창 포커스·탭 가시성을 잃으면 입력을 해제하고 일시정지한다.
- `PilotFlight`가 60Hz 고정 스텝으로 위치·수평 속도·고도·상승 속도·방위각을 갱신한다. 화면은 같은 상태로 기체, 추적/하향 카메라, 프로펠러, 먼지·풀, 계측값과 실제 궤적을 그린다. 수동 조종이 기체 좌표를 바꾸며 카메라만 옮기는 동작이 아니다.
- 경로 자동 비행은 경유점을 순서대로 추종하고, 가까워지면 감속하며 마지막 지점에 도착하면 정지한다. 조종 키나 가상 스틱 입력은 현재 위치를 유지한 채 수동 제어권을 가져오고, 자동 비행을 다시 누르면 남은 경유점으로 이어진다.
- 메인 페이지에 생성된 계획이 있으면 원래 미터 좌표·축척·순서를 보존하여 출발점 기준으로 평행 이동한다. 경로가 없으면 기본 5개 경유점 훈련 코스를 사용한다. 출발점 기준 ±40m를 벗어나는 계획은 변형하지 않고 기본 경로와 안내를 제공한다. 이 지도는 합성 지형이며 실제 시설이나 장애물을 검증하지 않는다.
- 계획 경로(황색 파선)와 실제 이동 궤적(밝은 올리브 실선)을 3D와 평면도에 함께 표시한다. 고도도 실제 궤적에 포함하며 위치·방위각·속도·이동 거리·진행 경유점이 갱신된다.
- 기존 `approachSim.ts`와 여섯 각본은 변경하지 않는다. 새 비행 모델은 별도의 웹 훈련용 운동 모델로, 실제 FC/PX4·충돌·배터리·공력 검증을 구현하거나 실기기에 명령을 보내는 기능은 아니다. 지면 높이와 훈련 구역·고도 경계를 적용한다.

### 대형 화면·비행 검증

- 1800×1009 화면에서 기본 비행 LCD는 약 1027×590px로, 이전 560×299px보다 면적이 약 3.6배 늘었다. 390×844에서도 가로 넘침 없이 조종기와 확대 기능을 사용한다.
- 실제 브라우저 키보드로 `W+D+↑+→`를 동시에 눌러 상승·회전·수평 이동과 기체 좌표 변화를 확인했다. 각 키를 놓으면 해당 입력이 해제되고, 모두 놓으면 감속 후 호버한다. 가상 스틱도 실제 기체 위치를 바꾼다.

- 조종기·관제·3D 전용 화면을 반복 전환해도 같은 Canvas와 비행 위치를 유지한다. 경유점 라벨을 DOM 포털 대신 3D 스프라이트로 그려 화면 전환 중 라벨 제거 오류를 해결했다. 모바일 전환과 WebGL 상실·재시도에서도 위치를 유지하고 JavaScript 오류가 없었다.
- 기존 여섯 접근 각본의 최종 거리·최대 속도·첫 도착 시간이 이전과 일치했다. 단위·회귀 검사 7개 파일 **118개 통과**, TypeScript 검사와 프로덕션 빌드 통과. 지연 로딩하는 3D 청크는 약 1.19MB(gzip 약 330KB)로 Vite의 크기 경고가 남는다.

## 전체 화면 3D 시험장 개편 (2026-10-10, 후속)

`Codex_DevDay/src/scene/Scene.tsx`, `Venue.tsx`, `SceneHtml.tsx`, `Hud.tsx`의 전체 화면 장면과 독립 대시보드 구조를 참고했다. 이 저장소의 기존 `approachSim.ts` 계산과 여섯 시험 각본은 변경하지 않았다.

- **배경 전체가 실시간 3D다.** React Three Fiber의 Canvas 한 개로 시험장·기체·태그·조명·그림자를 렌더링하고, 그 위에 주요 계측값·관제 패널·카메라 모니터·재생 타임라인을 배치한다. 배경 사진이나 사전 렌더링 영상은 사용하지 않는다.
- 시험장은 앞벽과 천장이 열린 구조로 다시 모델링했다. 계측대, 모니터, 장비 케이스, 센서 삼각대, 난간, 눈금이 있는 바닥을 배치한다. 기체에는 카본 프레임, 배터리, 기판, 모터, 프로펠러, 배선, 안테나, 착륙 다리, 하향 카메라를 구성한다. 외형과 시험장 치수는 시각 모델이며 실측 CAD가 아니다.
- `3D만 보기`와 `H`로 대시보드를 숨기고 복원한다. Canvas를 다시 만들지 않으며 시험 시점·설정·좌표를 유지한다. 3D 전용 화면의 Escape는 대시보드를 복원하고, 일반 화면의 Escape는 시뮬레이터를 닫는다.
- 전체 시험장, 기체 추적, 상공, 하향 카메라 시점을 제공한다. 구조물·비행 궤적·시야 및 거리 가이드는 각각 표시를 바꿀 수 있다. 관제 패널도 따로 숨길 수 있다.
- 가상 하향 영상은 같은 장면의 별도 카메라에서 약 8Hz로 생성한다. 가로 화각 55°와 4:3 영상비를 유지하고 HDR 장면을 ACES/sRGB로 변환한다. 기체·렌즈는 시각적 근사이며 보드의 실제 영상이 아니다.
- `sceneMath.ts`가 cm → m, 오른쪽 x → Three x, 앞 y → Three -z, 고도 → Three y 변환을 담당한다. 도착 허용 반경도 현재 제어 파라미터에서 읽는다. 일시정지 중 태그 가림은 장면과 카메라 상태에 즉시 반영되고, 제어기 출력은 다음 50ms 스텝에서 갱신한다.
- 정적 시험장 메시를 재질별로 병합하며 DPR 상한·자동 해상도 조절·성능 우선 모드를 제공한다. WebGL 컨텍스트 상실 시 동일 좌표의 평면도와 3D 재시도 기능을 제공한다.

### 라이브러리 및 Blender MCP 비교

| 항목 | 이번에 적용한 방법 | Blender MCP를 활용할 경우 |
|---|---|---|
| 실시간 화면 | Three.js + React Three Fiber, Drei 카메라·그리드·선·공간 라벨 | 제작한 모델을 GLB/glTF로 내보낸 뒤 웹 렌더러에 연결해야 함 |
| 모델 제작 | 코드에서 직접 만드는 원본 메시·재질·텍스처 | Blender에서 더 복잡한 곡면, UV, 재질과 베이크 작업을 할 때 유용 |

이번 작업에서는 Blender MCP를 실행하지 않았다. 연결된 Blender MCP 도구가 없으며, 요구한 실시간 제어 연결과 레이아웃에 맞춰 참고 프로젝트의 웹 렌더링 구성을 적용했다. 이후 정교한 기체 GLB를 제작하면 `sceneModels.ts`의 기체 외형만 교체하고 제어 계산·타임라인·대시보드를 유지할 수 있다.

근거: [React Three Fiber 소개](https://r3f.docs.pmnd.rs/getting-started/introduction), [Drei Controls](https://drei.docs.pmnd.rs/controls/introduction), [Blender MCP 프로젝트 문서](https://github.com/ahujasid/mcp-for-blender). Blender MCP는 Blender Foundation의 공식 제품이 아닌 커뮤니티 프로젝트다.

- 조종기 본체는 투명 PNG 프레임이며 3D로 복원한 본체 메시가 아니다. 중앙의 기체와 환경은 실시간 3D다. 생성 자산과 최종 프롬프트는 `web/public/controller/GENERATED_ASSET.md`에 기록했다.
- 단위·회귀 검사 6개 파일 **111개 통과**, TypeScript 검사·프로덕션 빌드 통과. 3D 지연 로딩 청크는 약 1.18MB(gzip 약 325KB)이며 Vite 크기 경고가 남는다.

### 조종기·방산 테마 브라우저 검증

- 1800×1009에서 조종기 LCD, 오른쪽 계측 패널, 재생 타임라인을 확인했다. 관제 화면·조종기·3D 전용 보기를 오가도 Canvas는 동일하며 3초 시점의 좌표 `(0.223708647, 1.2, 0.269017190)m`와 확대 1.3배가 유지된다.
- 실제 포인터 드래그로 오른쪽 스틱의 회전을 확인했고 놓은 뒤 카메라 좌표가 변하지 않음을 확인했다. 왼쪽 스틱의 방향키 이동·키 해제, 본체 재생 버튼, 시점 버튼과 확대 버튼도 확인했다.
- 조종기 안과 전체 화면 모두 하향 카메라는 4:3 비율을 유지한다. 390×844에서 가로 넘침 없이 프레임·확대 버튼·타임라인을 표시하고, 관제 패널의 제어 설정에 접근할 수 있다. 두 접점 터치 제스처로 확대하면 추적 카메라 거리가 줄어들고 같은 Canvas가 유지된다.
- 화질을 성능 우선으로 바꾸면서 WebGL 컨텍스트 상실을 강제로 발생시켜 평면도 대체·3D 재시도를 검증했다. 3초 시점·기체 좌표가 유지되고 Canvas는 하나이며 JavaScript 오류는 없었다.
- 여섯 각본을 끝 시점까지 탐색해 이전 결과와 일치함을 재확인했다. 핸드오버·바람 각본의 목표 속도 초과 경고도 유지된다.
- 메인 페이지의 지도 집중·복원, 지도 확대 100→150%·전체 맞춤, 편집·계획·기록 탭, 모바일 배치를 확인했다. 시뮬레이터를 닫으면 열기 버튼으로 포커스가 돌아온다.

## 설계 방향

한 화면에 작게 압축하던 기능을 임무 단계와 작업 탭으로 분리한다. 상태·단위·출처는 텍스트로 함께 표시하며, 미연결·오래된 보고를 정상으로 추정하지 않는다. 지도와 3D 장면은 중심 작업 영역으로 두고 설정은 별도 탭으로 이동한다.

## 전술지휘소

- 편집, 계획, 기록을 탭으로 나누고 임무 설정 → 계획 검증 → 승인·리허설의 진행 상태를 보여준다.
- 지도는 명시적으로 태그 추가 도구를 선택한 뒤 편집한다. 기본 클릭은 개체 선택이다.
- 지도 확대·축소·이동·초기화와 지형/도식 전환, 표시 레이어를 제공한다.
- 창 크기와 무관하게 필드의 가로·세로 축척을 유지한다. 계획 전 연결선과 서버가 반환한 실제 경유점 경로를 구분하며, 새 계획을 시작하면 이전 지표를 지운다.
- 생성형 시험장 사진은 **합성 지형·로컬 좌표**임을 표시한다. 실제 시설·지리 좌표·장애물 검증 자료가 아니다.
- 상단에서 시뮬레이터를 바로 열 수 있다. 최초 진입 때만 3D 코드를 불러온다.

## 가상 시험실

- Three.js로 카본 기체, 모터·프로펠러, 배터리, 하향 카메라, 시험장 바닥과 조명·그림자를 그린다.
- 입체, 상공, 하향 카메라를 전환하며 입체 시점은 회전·확대·이동할 수 있다.
- 하향 카메라는 4:3 영상비와 가로 시야 55°를 유지한다. 넓은 화면의 여백 때문에 센서 시야가 바뀌지 않는다.
- 위치는 제어기 시뮬레이션의 cm 값을 m로 변환해 그대로 사용한다. 기체 자세와 렌즈·재질은 시각 모델이다.
- 재생·정지·초기화·배속과 사건 타임라인을 제공한다. 과거 시점으로 이동할 때 기존 제어기와 입력 기록을 결정적으로 다시 실행한다.
- 실시간 계측, 환경·고장, 제어 설정을 분리한다. 목표 속도와 실제 모델 속도, 고정 고도를 구별한다.
- WebGL 실패 시 같은 좌표를 평면도로 표시한다. 장면·버퍼·텍스처·RAF는 닫을 때 정리한다.
- 시뮬레이션은 실제 기체에 연결하거나 명령을 보내지 않는다. 화면의 태그는 시각화용이며 현장 출력 카드가 아니다.

## 하드웨어 패널

- 연결·상태, 접근 제어, 안전·지상 시험 탭으로 나눴다.
- 잠금 이유는 상단에 유지하고, 연결 실패의 상세 원인은 펼쳐 볼 수 있다.
- 명령 허용목록·송신 직전 상태 재확인·확인 문구·일회성 토큰·RAM 전용 쓰기·최대 목표 속도 10cm/s는 그대로다.

## 자산과 실행

`web/public/terrain/spider-ortho-v2.png`는 내장 이미지 생성 도구로 만든 새 자산이다. 생성 프롬프트와 용도는 `web/public/terrain/GENERATED_ASSET.md`에 기록했다. 기존 이미지도 보존했다.

의존성을 설치한 후 기존과 같은 명령으로 실행한다.

```powershell
cd web
npm ci
npm test -- --run
npm run build
```

실기기 없이 확인하려면 `D4D_HARDWARE_WRITES=0`, `D4D_FC_PORT=SIMULATION_NO_DEVICE`, `D4D_LLM_PROVIDER=none`을 사용한다. 실사에 가까운 화면은 기체의 실제 비행 성능·센서 판독·킬 동작을 검증한 증거가 아니다.

## 검증 기록

2026-10-10, 실기기 송신을 끈 로컬 API와 프로덕션 빌드에서 확인했다.

- `npm test -- --run`: 4개 파일, **99개 통과**. 기존 90개와 재생 회귀 9개다. 여섯 각본의 모든 프레임을 일반 순차 실행과 비교하고, 시점 범위·50ms 스텝·기록된 외란/파라미터·일시정지 입력·입력 불변성을 검사했다.
- `npm run build`: TypeScript 검사와 Vite 빌드 통과. 3D 모듈은 지연 로딩한다. 약 657KB(압축 전)의 3D 청크에 Vite 크기 경고가 남으며, gzip은 약 172KB다.
- 브라우저 크기 1440×900, 1100×800, 390×844에서 배치·스크롤·조작을 확인했다. 모바일 가로 넘침은 없었다. Escape로 닫은 뒤 열기 버튼으로 포커스가 돌아왔다.
- 정상 접근의 3초 시점 탐색에서 9.6cm/s·35.0cm를 표시했다. 일시정지 상태에서 태그를 가리면 시각 장면에 가림판이 나타나고, 다음 제어 스텝 반영 안내가 나온다.
- 핸드오버 각본의 종료 결과는 최종 거리 2.7cm, 최대 모델 속도 21.5cm/s, 첫 도착 9.2초였다. 목표 상한 10cm/s 초과를 숨기지 않고 경고한다.
- Three.js 입체 장면과 4:3 하향 영상, 카메라 전환, 그림자·태그·기체 좌표를 브라우저에서 확인했다. JavaScript 오류는 없었다. 이 장치의 그래픽 드라이버가 셰이더 정밀도 경고를 출력하지만 렌더링은 정상 작동했다.
- 데모 계획 생성 → 실제 27개 경유점 지도 표시 → 임무 승인 → 패키지·플랜 카드·드릴 링크 활성화를 확인했다. 지도 확대 100→150%와 전체 맞춤도 확인했다.
- 지도 기본 클릭은 노드를 추가하지 않는다. 편집·추가를 켠 후 중앙 클릭은 `(20, 12)m`에 노드를 추가했고 기존 승인 링크는 즉시 잠겼다. 모바일 지도 362×217.2px에서 40:24 필드 비율과 원형 핀의 같은 가로·세로 크기도 확인했다. 인접 라벨은 실제 핀 좌표를 움직이지 않고 분산한다.
- 하드웨어 패널의 탭을 이동해 미연결 상태에서 6개 차단 이유와 잠긴 명령을 확인했다. 실제 BLE 연결·FC 쓰기·기체 작동은 수행하지 않았다.

백엔드와 제어기 계산은 이 UI 개편에서 변경하지 않았다. 앞선 인수 작업의 Python 검증은 `Ran 180, OK (skipped=2)`이며 상세 집계와 스킵 사유는 `CODEX_VERIFICATION.md`에 있다. WebGL 비지원 장치의 자동 평면도 대체는 코드 경로를 검토했으며 해당 장치를 이용한 실측은 하지 않았다.
