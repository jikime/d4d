# 전술지휘소·3D 시뮬레이터 UI/UX 개편

2026-10-10. -25 지원 작업본 위에서 화면 구조와 시각화를 개편했다.

## 방산 해커톤 운용 화면·야외 훈련장 (2026-10-10, 추가 개편)

- 메인·하드웨어 패널·시뮬레이터를 검정, 저채도 국방색과 밝은 올리브 강조색으로 통일했다. 경고의 황색·적색 의미는 유지한다. 메인 상단에 현재 시나리오의 훈련 구역, 노드 수, 링크 두절 정책을 표시하고 지도 집중/작업 패널 복원을 제공한다. 실제 계획 경로에 흐르는 선을 적용하고 패널 전환을 부드럽게 처리한다. 동작 줄이기 설정에서는 장식 애니메이션을 끈다.
- 실내 시험실과 야외 훈련장을 전환한다. 야외에는 높낮이가 있는 지형, 착륙 패드, 관제 컨테이너, 장비 케이스, 관측 마스트·풍향계, 펜스, 바위·수목·풀을 구성했다. 정밀 접근 구역의 지면은 평탄하게 유지한다. 주간/해질녘 조명과 대기 안개·그림자는 같은 장면에 적용된다.
- 기체를 무광 국방색 외피와 카본 프레임으로 구성하고 방열 홈, 나사, 배터리 잠금부·스트랩, 배선, 센서 렌즈, 전방 짐벌, 항법등과 하향 카메라를 추가했다. 특정 제조사의 인증 모델이나 실측 CAD 복제본은 아니다.
- 인접 프로펠러는 서로 반대 방향, 대각선은 같은 방향으로 회전한다. 재생 속도와 가상 킬에 따라 모터 표시가 가속·감속하고, 프로펠러 잔상도 변한다. 제어 출력에 따른 기체 기울기와 반대 방향 짐벌 보정, 기체 아래 먼지·풀의 반응을 구현했다. 기체의 고정 부분은 재질별 병합, 식생·바위는 인스턴싱으로 처리한다.
- 20Hz 제어 계산을 바꾸지 않고 화면 좌표를 부드럽게 보간한다. 일시정지·시점 탐색 시 계산된 좌표로 즉시 맞춘다. 카메라 모니터와 추적 카메라는 표시 중인 동일 기체 위치를 사용한다. 먼지·풀·풍향계는 재생 시간에 연결되어 일시정지 시 멈춘다.
- 확대·축소 버튼과 배율 표시를 추가했다. 전체/상공은 회전·이동·휠·터치 확대, 추적/하향 카메라는 버튼·휠 확대를 지원한다. 하향 화면의 확대는 디지털 크롭이며 원본 4:3·가로 화각 55° 카메라 모니터는 유지한다.
- `web/public/terrain/field-ground-albedo-v1.png`는 내장 이미지 생성 도구로 만든 새 흙·자갈 재질이다. [생성 프롬프트와 용도](../web/public/terrain/GENERATED_ASSET.md)를 기록했다. 3D 형상은 코드로 만들고 이미지는 그 표면에 적용했다. 이미지에서 복원한 3D 자산이라고 표시하지 않는다.

### 공개 자료 참고와 모델의 범위

[Skydio X10 공개 자료](https://www.skydio.com/x10)의 기체·센서 구성을 외형 참고로, [PX4 Gazebo 문서](https://docs.px4.io/main/en/sim_gazebo_gz/)의 환경·시뮬레이션 분리를 설계 참고로 사용했다. 제조사 이미지나 모델은 복제·재배포하지 않았다.

이번 작업은 운용 UI와 실시간 시각화를 개선한다. 기존의 고정 고도·수평 정밀 접근 모델과 여섯 시나리오는 유지되며 PX4 SITL, 6자유도 비행 역학, 충돌 계산, 실제 RPM·배터리·추력 모델을 연결한 것은 아니다. 하강풍의 먼지·풀 반응은 고도·거리·가상 모터 상태를 이용한 표시 모델이며 CFD 결과가 아니다. 실기기 제어 로직·송신 권한은 이 개편에서 변경하지 않았다.

## 전체 화면 3D 시험장 개편 (2026-10-10, 후속)

`Codex_DevDay/src/scene/Scene.tsx`, `Venue.tsx`, `SceneHtml.tsx`, `Hud.tsx`의 전체 화면 장면과 독립 대시보드 구조를 참고했다. 이 저장소의 기존 `approachSim.ts` 계산과 여섯 시험 각본은 변경하지 않았다.

- **배경 전체가 실시간 3D다.** React Three Fiber의 Canvas 한 개로 시험장·기체·태그·조명·그림자를 렌더링하고, 그 위에 주요 계측값·관제 패널·카메라 모니터·재생 타임라인을 배치한다. 배경 사진이나 사전 렌더링 영상은 사용하지 않는다.
- 시험장은 앞벽과 천장이 열린 구조로 다시 모델링했다. 계측대, 모니터, 장비 케이스, 센서 삼각대, 난간, 눈금이 있는 바닥을 배치한다. 기체에는 카본 프레임, 배터리, 기판, 모터, 프로펠러, 배선, 안테나, 착륙 다리, 하향 카메라를 구성한다. 외형과 시험장 치수는 시각 모델이며 실측 CAD가 아니다.
- `3D만 보기`와 `H`로 대시보드를 숨기고 복원한다. Canvas를 다시 만들지 않으며 시험 시점·설정·좌표를 유지한다. 3D 전용 화면의 Escape는 대시보드를 복원하고, 일반 화면의 Escape는 시뮬레이터를 닫는다.
- 전체 시험장, 기체 추적, 상공, 하향 카메라 시점을 제공한다. 구조물·비행 궤적·시야 및 거리 가이드는 각각 표시를 바꿀 수 있다. 관제 패널도 따로 숨길 수 있다.
- 가상 하향 영상은 같은 장면의 별도 카메라에서 약 8Hz로 생성한다. 가로 화각 55°와 4:3 영상비를 유지하고 HDR 장면을 ACES/sRGB로 변환한다. 기체·렌즈는 시각적 근사이며 보드의 실제 영상이 아니다.
- `sceneMath.ts`가 cm → m, 오른쪽 x → Three x, 앞 y → Three -z, 고도 → Three y 변환을 담당한다. 도착 허용 반경도 현재 제어 파라미터에서 읽는다. 일시정지 중 태그 가림은 장면과 카메라 상태에 즉시 반영되고, 제어기 출력은 다음 50ms 스텝에서 갱신한다.
- 정적 시험장 메시를 재질별로 병합하며 DPR 상한·자동 해상도 조절·성능 우선 모드를 제공한다. WebGL 컨텍스트 상실 시 동일 좌표의 평면도와 3D 재시도 기능을 제공한다.

### 라이브러리 및 Blender MCP 비교

| 항목 | 이번에 적용한 방법 | Blender MCP를 활용할 경우 |
|---|---|---|
| 실시간 화면 | Three.js + React Three Fiber, Drei 카메라·그리드·선·공간 라벨 | 제작한 모델을 GLB/glTF로 내보낸 뒤 웹 렌더러에 연결해야 함 |
| 모델 제작 | 코드에서 직접 만드는 원본 메시·재질·텍스처 | Blender에서 더 복잡한 곡면, UV, 재질과 베이크 작업을 할 때 유용 |
| 후처리 | `@react-three/postprocessing`, `postprocessing`의 Bloom·ACES | Blender의 조명·렌더 결과가 웹의 실시간 렌더 결과를 그대로 대체하지는 않음 |
| 시험 흐름 연결 | 기존 20Hz 제어 계산·각본·입력 재생을 그대로 연결 | 모델 제작과 별개로 같은 제어 데이터 연결 작업이 필요 |

이번 작업에서는 Blender MCP를 실행하지 않았다. 연결된 Blender MCP 도구가 없으며, 요구한 실시간 제어 연결과 레이아웃에 맞춰 참고 프로젝트의 웹 렌더링 구성을 적용했다. 이후 정교한 기체 GLB를 제작하면 `sceneModels.ts`의 기체 외형만 교체하고 제어 계산·타임라인·대시보드를 유지할 수 있다.

근거: [React Three Fiber 소개](https://r3f.docs.pmnd.rs/getting-started/introduction), [Drei Controls](https://drei.docs.pmnd.rs/controls/introduction), [Blender MCP 프로젝트 문서](https://github.com/ahujasid/mcp-for-blender). Blender MCP는 Blender Foundation의 공식 제품이 아닌 커뮤니티 프로젝트다.

### 후속 검증

- 단위·회귀 검사 5개 파일 **104개 통과**. 기존 99개와 좌표 변환·센서 비율 검사 5개다. 여섯 각본의 순차 계산과 재생 결과 일치 검사를 유지한다.
- 브라우저에서 여섯 각본을 끝 시점으로 이동해 결과를 확인했다. 정상 접근은 최종 거리 1.5cm / 최대 속도 9.7cm/s / 첫 도착 10.9초, 핸드오버는 2.7cm / 21.5cm/s / 9.2초다. 목표 속도 초과 경고도 유지한다.
- 3초 시점은 9.6cm/s·35.0cm를 표시한다. 대시보드를 숨겨도 동일한 Canvas, 3초 시점, 기체 좌표가 유지된다. 태그 가림, 구조물 숨김, 카메라 시점 전환, 4:3 하향 영상도 확인했다.
- 390×844에서 가로 넘침 없이 3D·계측값·타임라인을 표시하며, 관제 패널 열기·설정 슬라이더·3D 전용 보기·복원 동작을 확인했다.
- 화질 전환 직후 WebGL 컨텍스트 상실을 강제로 발생시켜 평면도 전환과 3D 재시도를 확인했다. JavaScript 오류 없이 3초 시점·기체 좌표가 유지되고 Canvas는 하나만 생성된다. 시뮬레이터를 닫으면 원래 열기 버튼으로 포커스가 돌아온다.
- `npm run build`의 TypeScript 검사와 프로덕션 빌드를 통과했다.
- 3D 코드는 시뮬레이터를 열 때 지연 로딩한다. 전체 3D 청크가 약 1.14MB(gzip 약 314KB)로 커져 Vite의 청크 크기 경고가 남는다.

## 조종기 디스플레이 개편 (2026-10-10)

- 첨부된 조종기 사진을 참고한 검은 SPIDER 본체·안테나·스틱 프레임을 만들었다. 중앙 LCD 영역은 실제 3D Canvas이며 기존 여섯 각본의 좌표·재생 상태·계측값을 그대로 사용한다. 기본 화면은 조종기에서 기체를 추적하는 시점이다.
- 왼쪽 스틱은 카메라 이동, 오른쪽 스틱은 카메라 회전에 연결했다. 드래그·터치·방향키를 지원하며 놓기·포커스 상실·화면 전환 시 입력을 해제한다. 이 스틱은 가상 카메라를 움직이며 기존 자동 접근 계산을 변경하지 않는다.
- 본체 버튼으로 재생·정지, 확대·축소, 시점 초기화, 전체·상공·하향·추적 시점, 디스플레이 확대와 닫기를 조작한다. LCD 위에 현재 상태·속도·거리·고도를 표시한다. 추적·하향 시점에서도 마우스 휠과 두 손가락 확대를 지원한다.
- 상단의 관제 화면 전환과 `3D만 보기` / `H`로 화면 구성을 바꾼다. 같은 Canvas를 유지하여 조종기 표시를 벗어나도 재생 시점·기체 좌표·카메라 확대가 이어진다. 작은 화면에는 별도의 디스플레이 확대 버튼을 제공한다.
- 조종기 본체는 투명 PNG 프레임이며 3D로 복원한 본체 메시가 아니다. 중앙의 기체와 환경은 실시간 3D다. 생성 자산과 최종 프롬프트는 `web/public/controller/GENERATED_ASSET.md`에 기록했다.
- 단위·회귀 검사 6개 파일 **111개 통과**, TypeScript 검사·프로덕션 빌드 통과. 3D 지연 로딩 청크는 약 1.18MB(gzip 약 325KB)이며 Vite 크기 경고가 남는다.

### 조종기·방산 테마 브라우저 검증

- 1800×1009에서 조종기 LCD, 오른쪽 계측 패널, 재생 타임라인을 확인했다. 관제 화면·조종기·3D 전용 보기를 오가도 Canvas는 동일하며 3초 시점의 좌표 `(0.223708647, 1.2, 0.269017190)m`와 확대 1.3배가 유지된다.
- 실제 포인터 드래그로 오른쪽 스틱의 회전을 확인했고 놓은 뒤 카메라 좌표가 변하지 않음을 확인했다. 왼쪽 스틱의 방향키 이동·키 해제, 본체 재생 버튼, 시점 버튼과 확대 버튼도 확인했다.
- 조종기 안과 전체 화면 모두 하향 카메라는 4:3 비율을 유지한다. 390×844에서 가로 넘침 없이 프레임·확대 버튼·타임라인을 표시하고, 관제 패널의 제어 설정에 접근할 수 있다. 두 접점 터치 제스처로 확대하면 추적 카메라 거리가 줄어들고 같은 Canvas가 유지된다.
- 화질을 성능 우선으로 바꾸면서 WebGL 컨텍스트 상실을 강제로 발생시켜 평면도 대체·3D 재시도를 검증했다. 3초 시점·기체 좌표가 유지되고 Canvas는 하나이며 JavaScript 오류는 없었다.
- 여섯 각본을 끝 시점까지 탐색해 이전 결과와 일치함을 재확인했다. 핸드오버·바람 각본의 목표 속도 초과 경고도 유지된다.
- 메인 페이지의 지도 집중·복원, 지도 확대 100→150%·전체 맞춤, 편집·계획·기록 탭, 모바일 배치를 확인했다. 시뮬레이터를 닫으면 열기 버튼으로 포커스가 돌아온다.

## 설계 방향

한 화면에 작게 압축하던 기능을 임무 단계와 작업 탭으로 분리한다. 상태·단위·출처는 텍스트로 함께 표시하며, 미연결·오래된 보고를 정상으로 추정하지 않는다. 지도와 3D 장면은 중심 작업 영역으로 두고 설정은 별도 탭으로 이동한다.

## 전술지휘소

- 편집, 계획, 기록을 탭으로 나누고 임무 설정 → 계획 검증 → 승인·리허설의 진행 상태를 보여준다.
- 지도는 명시적으로 태그 추가 도구를 선택한 뒤 편집한다. 기본 클릭은 개체 선택이다.
- 지도 확대·축소·이동·초기화와 지형/도식 전환, 표시 레이어를 제공한다.
- 창 크기와 무관하게 필드의 가로·세로 축척을 유지한다. 계획 전 연결선과 서버가 반환한 실제 경유점 경로를 구분하며, 새 계획을 시작하면 이전 지표를 지운다.
- 생성형 시험장 사진은 **합성 지형·로컬 좌표**임을 표시한다. 실제 시설·지리 좌표·장애물 검증 자료가 아니다.
- 상단에서 시뮬레이터를 바로 열 수 있다. 최초 진입 때만 3D 코드를 불러온다.

## 가상 시험실

- Three.js로 카본 기체, 모터·프로펠러, 배터리, 하향 카메라, 시험장 바닥과 조명·그림자를 그린다.
- 입체, 상공, 하향 카메라를 전환하며 입체 시점은 회전·확대·이동할 수 있다.
- 하향 카메라는 4:3 영상비와 가로 시야 55°를 유지한다. 넓은 화면의 여백 때문에 센서 시야가 바뀌지 않는다.
- 위치는 제어기 시뮬레이션의 cm 값을 m로 변환해 그대로 사용한다. 기체 자세와 렌즈·재질은 시각 모델이다.
- 재생·정지·초기화·배속과 사건 타임라인을 제공한다. 과거 시점으로 이동할 때 기존 제어기와 입력 기록을 결정적으로 다시 실행한다.
- 실시간 계측, 환경·고장, 제어 설정을 분리한다. 목표 속도와 실제 모델 속도, 고정 고도를 구별한다.
- WebGL 실패 시 같은 좌표를 평면도로 표시한다. 장면·버퍼·텍스처·RAF는 닫을 때 정리한다.
- 시뮬레이션은 실제 기체에 연결하거나 명령을 보내지 않는다. 화면의 태그는 시각화용이며 현장 출력 카드가 아니다.

## 하드웨어 패널

- 연결·상태, 접근 제어, 안전·지상 시험 탭으로 나눴다.
- 잠금 이유는 상단에 유지하고, 연결 실패의 상세 원인은 펼쳐 볼 수 있다.
- 명령 허용목록·송신 직전 상태 재확인·확인 문구·일회성 토큰·RAM 전용 쓰기·최대 목표 속도 10cm/s는 그대로다.

## 자산과 실행

`web/public/terrain/spider-ortho-v2.png`는 내장 이미지 생성 도구로 만든 새 자산이다. 생성 프롬프트와 용도는 `web/public/terrain/GENERATED_ASSET.md`에 기록했다. 기존 이미지도 보존했다.

의존성을 설치한 후 기존과 같은 명령으로 실행한다.

```powershell
cd web
npm ci
npm test -- --run
npm run build
```

실기기 없이 확인하려면 `D4D_HARDWARE_WRITES=0`, `D4D_FC_PORT=SIMULATION_NO_DEVICE`, `D4D_LLM_PROVIDER=none`을 사용한다. 실사에 가까운 화면은 기체의 실제 비행 성능·센서 판독·킬 동작을 검증한 증거가 아니다.

## 검증 기록

2026-10-10, 실기기 송신을 끈 로컬 API와 프로덕션 빌드에서 확인했다.

- `npm test -- --run`: 4개 파일, **99개 통과**. 기존 90개와 재생 회귀 9개다. 여섯 각본의 모든 프레임을 일반 순차 실행과 비교하고, 시점 범위·50ms 스텝·기록된 외란/파라미터·일시정지 입력·입력 불변성을 검사했다.
- `npm run build`: TypeScript 검사와 Vite 빌드 통과. 3D 모듈은 지연 로딩한다. 약 657KB(압축 전)의 3D 청크에 Vite 크기 경고가 남으며, gzip은 약 172KB다.
- 브라우저 크기 1440×900, 1100×800, 390×844에서 배치·스크롤·조작을 확인했다. 모바일 가로 넘침은 없었다. Escape로 닫은 뒤 열기 버튼으로 포커스가 돌아왔다.
- 정상 접근의 3초 시점 탐색에서 9.6cm/s·35.0cm를 표시했다. 일시정지 상태에서 태그를 가리면 시각 장면에 가림판이 나타나고, 다음 제어 스텝 반영 안내가 나온다.
- 핸드오버 각본의 종료 결과는 최종 거리 2.7cm, 최대 모델 속도 21.5cm/s, 첫 도착 9.2초였다. 목표 상한 10cm/s 초과를 숨기지 않고 경고한다.
- Three.js 입체 장면과 4:3 하향 영상, 카메라 전환, 그림자·태그·기체 좌표를 브라우저에서 확인했다. JavaScript 오류는 없었다. 이 장치의 그래픽 드라이버가 셰이더 정밀도 경고를 출력하지만 렌더링은 정상 작동했다.
- 데모 계획 생성 → 실제 27개 경유점 지도 표시 → 임무 승인 → 패키지·플랜 카드·드릴 링크 활성화를 확인했다. 지도 확대 100→150%와 전체 맞춤도 확인했다.
- 지도 기본 클릭은 노드를 추가하지 않는다. 편집·추가를 켠 후 중앙 클릭은 `(20, 12)m`에 노드를 추가했고 기존 승인 링크는 즉시 잠겼다. 모바일 지도 362×217.2px에서 40:24 필드 비율과 원형 핀의 같은 가로·세로 크기도 확인했다. 인접 라벨은 실제 핀 좌표를 움직이지 않고 분산한다.
- 하드웨어 패널의 탭을 이동해 미연결 상태에서 6개 차단 이유와 잠긴 명령을 확인했다. 실제 BLE 연결·FC 쓰기·기체 작동은 수행하지 않았다.

백엔드와 제어기 계산은 이 UI 개편에서 변경하지 않았다. 앞선 인수 작업의 Python 검증은 `Ran 180, OK (skipped=2)`이며 상세 집계와 스킵 사유는 `CODEX_VERIFICATION.md`에 있다. WebGL 비지원 장치의 자동 평면도 대체는 코드 경로를 검토했으며 해당 장치를 이용한 실측은 하지 않았다.
